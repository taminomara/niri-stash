## Session environment the daemon lives in

- `XDG_RUNTIME_DIR=/run/user/1000`.
- `NIRI_SOCKET=/run/user/1000/niri.wayland-1.1572.sock` and `WAYLAND_DISPLAY=wayland-1` are both
  present in the **systemd user manager environment** (`systemctl --user show-environment`), so a user
  service inherits them without a wrapper. The socket filename embeds the display and niri's pid, so it
  changes on every niri restart; that is the instance identity T4 relies on.
- `graphical-session.target` is active and `Wants=` the user's own services. Existing precedent for a
  hand-rolled user daemon (`~/.config/systemd/user/asus-hotkey-notify.service`):
  `PartOf=graphical-session.target`, `After=graphical-session.target`, `Restart=always`, `RestartSec=3`,
  `WantedBy=graphical-session.target`, `ExecStart=%h/.local/bin/<binary>`. Second precedent
  `micmute-led-sync.service` uses `Restart=on-failure`, `RestartSec=2`, and its script exits non-zero
  when its upstream subscription ends so systemd restarts it.
- Binaries the user runs from keybinds live on `PATH` via `~/.local/bin` and `~/.cargo/bin`
  (`~/.local/bin` holds the existing daemon scripts; `~/.cargo/bin` is where `cargo install` puts
  binaries). Keybinds in `~/.config/niri/cfg/keybinds.kdl` follow the shape
  `Mod+X hotkey-overlay-title="…" { spawn "cmd" "arg"; }`. No binding currently uses `Mod+S`,
  `Mod+Shift+S` is taken (screenshot), `Mod+G`, `Mod+H`, `Mod+J`, `Mod+K`, `Mod+N`, `Mod+R`, `Mod+U`,
  `Mod+Y` are free (checked against the binds block).

## niri mechanics verified in source (v26.04) that the plan must honor

- **Reported position frame vs. request frame differ.** IPC `WindowLayout.tile_pos_in_workspace_view`
  for floating windows is `Data::logical_pos`, which is **output-relative** (working-area origin added
  back in `Data::recompute_logical_pos`, `src/layout/floating.rs`). `move-floating-window` with
  `PositionChange::SetFixed(v)` sets `pos = v + working_area.loc` (`FloatingSpace::move_window`,
  `src/layout/floating.rs` ~line 954), i.e. **working-area-relative**. With the bar on top the two
  frames differ by the bar height on y. `AdjustFixed(delta)` adds to the output-relative position
  directly and needs no knowledge of the working area.
- **Clamp:** `clamp(size/4, 10, 75)` px must stay visible per axis, applied relative to the working
  area on every size or working-area change (`Data::recompute_logical_pos`, `Data::update`,
  `Data::update_config`). A move far past the edge is clamped, not rejected.
- **Size requests:** `FloatingSpace::set_window_width/height` clamp to the window's min/max
  (`ensure_min_max_size`) and call `request_size_once`; the app answers asynchronously.
- **Actions never fail for a bad window id.** `Request::Action` replies `Response::Handled` after
  `validate_action` (which only checks screenshot paths). `SetWindowWidthById` etc. look the id up and
  silently do nothing when it is gone (`src/input/mod.rs` ~1986). The daemon cannot learn of a vanished
  window from the action reply; only from the snapshot and `WindowClosed`.
- **Focus to tiling on an empty tiling layout is a no-op** (`Workspace::switch_focus_floating_tiling`).
  `focus-tiling` exists as an action (`Action::FocusTiling {}`).
- **Focus `None` sources:** every non-layout keyboard focus (layer shell, `Mru`, `Overview`,
  `LockScreen`, `ScreenshotUi`, `ExitConfirmDialog`, empty layout) — `src/niri.rs`
  `update_keyboard_focus`; emitted as `WindowFocusChanged { id: None }` in `src/ipc/server.rs`.
- **Window ids** come from a process-global counter (`src/window/mapped.rs`) and restart with niri.
- **Re-floating restores the last floating size/pos** (`Tile.floating_window_size`, `floating_pos`;
  `FloatingSpace::add_tile_at`). Floating windows are never fullscreen; fullscreen moves them to the
  scrolling layout with `restore_to_floating`.
- **Windows/Workspaces replies** are served from the same `event_stream_state` the stream is built from
  (`src/ipc/server.rs`), so a request-socket snapshot reflects everything already emitted.
